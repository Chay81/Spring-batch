# Final Commit

# Spring Batch Scalable File Processing System

# Description
A production-grade Spring Batch application for processing large CSV files using parallel partitioning, metadata tracking, and idempotent data ingestion.
The system supports multi-threaded file processing, duplicate filtering, retry mechanisms for failed jobs, and real-time metrics monitoring.

## Features
- Parallel file processing using Spring Batch partitioning
- Multi-file ingestion (CSV → Database)
- Retry mechanism for failed files
- File-level metadata tracking (status, counts, timestamps)
- Metrics integration with Prometheus
- Duplicate record filtering (idempotent processing)
- Chunk-based high-performance processing (1M+ records tested)
- Automatic file archival after processing

## Architecture

Input Files (CSV)
        ↓
File Partitioner (creates partitions per file)
        ↓
Parallel Processing (Thread Pool)
        ↓
Reader → Processor → Writer
        ↓
Database (Users Table)
        ↓
Metadata Table (file_metadata)
        ↓
File Archival (input → archive)


## Tech Stack

- Java 17+
- Spring Boot
- Spring Batch
- Spring Data JPA
- PostgreSQL
- Micrometer + Prometheus
- Maven

## How It Works
1. The system scans the input directory for CSV files.
2. Each file is assigned to a separate partition.
3. Files are processed in parallel using multiple threads.
4. Data is read, validated, and written to the database in chunks.
5. Duplicate records are filtered during processing.
6. Metadata is updated for each file:
   - Start Time
   - End Time
   - Status (NEW, COMPLETED, FAILED)
   - Record Count
7. Processed files are moved to an archive directory.
8. Failed files are retried automatically in the next run.

## Sample Execution
- Total Records Processed: 1,000,000

- Duplicates Skipped: 19
- Files Processed: 4
- Processing Time: ~20 seconds
- Threads Used: 4+


## Tables
### users
Stores processed user records.

### file_metadata
Tracks file processing status:
- file_name
- status (NEW, COMPLETED, FAILED)
- record_count
- start_time
- end_time


## Run the Application

1. Place CSV files in:
   ./input/

2. Configure DB in application.yml

3. Run:
   mvn spring-boot:run

4. Trigger job:
   POST /run-job


## Retry Mechanism
- Files with status FAILED are retried automatically
- COMPLETED files are skipped
- Duplicate records are safely ignored during retries


## Metrics
Exposed via:
- /actuator/prometheus

Includes:
- Total DB writes
- Writes per thread
- Active threads
- Unique threads used
